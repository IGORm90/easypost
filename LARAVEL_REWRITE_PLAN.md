# ЧАСТЬ A. Инвентаризация функций текущего проекта

## A1. Архитектура (как есть сейчас)

| Компонент | Технология | Роль |
|---|---|---|
| `apps/backend` | NestJS | REST API (private + public API + OAuth-сервер) |
| `apps/orchestrator` | NestJS + Temporal | Фоновые задачи: публикация, ретраи, обновление токенов, рассылки |

## A3. Полный список функций

### 1. Аутентификация и аккаунты
- Регистрация / логин / выход, JWT.
- Восстановление пароля (forgot / forgot-return), активация email, повторная отправка активации.
- Соц-логин OAuth (GitHub, Google/generic OAuth провайдер — Authentik-совместимый), mobile OAuth callback.
- Проверка «разрешена ли регистрация» (закрытый self-hosted режим).
- Личный профиль, смена настроек, email-уведомления вкл/выкл.
- API-ключ пользователя + ротация ключа.
- Impersonation (вход под пользователем для суперадмина).

### 2. Организации и команды
- Мульти-организации, переключение между организациями.
- Приглашение участников по ссылке, вступление в организацию.
- Роли и права (SUPERADMIN / ADMIN / USER), удаление участников.
- Настройки организации: короткие ссылки (shortlink preference), подписи.

### 3. Каналы (Integrations) — подключение соцсетей
- OAuth-подключение канала, повторное подключение (refresh), отключение/включение канала, удаление.
- ~37 провайдеров: X (Twitter), LinkedIn (личный + страница), Facebook, Instagram (+standalone),
  Threads, Pinterest, Reddit, Telegram, VK
- Группировка каналов, кастомные имена/никнеймы, «customer» (клиент-агентство) на канал.
- Настройки канала (per-provider settings), тайм-слоты публикации по каналу.
- Автообновление истёкших токенов, уведомление о «сломанном» канале.
- Упоминания (mentions) — поиск аккаунтов внутри провайдера.
- Кастомные функции провайдера (сабреддиты Reddit, каналы Discord/Slack, доски Pinterest и т.п.).

### 4. Посты и календарь
- Календарь публикаций (день/неделя/месяц), drag-and-drop переноса даты.
- Создание поста сразу в несколько каналов, с per-channel вариациями текста и медиа.
- Треды/цепочки постов (несколько сообщений в одном посте).
- Черновики, превью поста в стиле каждой соцсети.
- Статусы: очередь / опубликован / ошибка / черновик.
- Автоподбор ближайшего свободного слота (find-slot).
- Теги постов (CRUD + фильтрация календаря по тегам).
- Комментарии команды к посту (внутреннее обсуждение).
- Дублирование, удаление группы постов, редактирование даты.
- Публичная страница превью поста (share-ссылка + комментарии).
- Валидация контента под требования конкретной сети (лимиты символов, медиа).
- Сокращение ссылок (short links) и подстановка UTM.
- Подписи (signatures) — авто-добавление подписи к постам.
- Sets — сохранённые наборы каналов для быстрого выбора.
- Повторная публикация при ошибке, отчёт по «пропущенным» постам.

### 5. Медиа-библиотека
- Загрузка файлов (локальное хранилище или S3-совместимое Cloudflare R2).
- Загрузка по URL, загрузка через сервер, простая загрузка.
- Список медиа с пагинацией, удаление, метаданные (информация о файле).
- Генерация изображений AI, генерация изображения по промпту.
- Генерация видео (Veo3, image-slides), опции видео, лимиты по тарифу.
- Встроенный редактор изображений (Polotno).

### 6. AI / агенты (Copilot)
- AI-чат-ассистент для написания постов.
- AI-агент: генерация серии постов по теме/категории (agent graph, topics/categories).
- Генератор постов из заданного контента (generator / generator draft).
- Кредиты на AI-операции (учёт и списание).
- История тредов чата.
- Автозаполнение и переписывание текста под конкретную соцсеть.

### 7. Автопостинг и автоматизации
- **AutoPost**: автоматическая публикация из RSS-ленты по расписанию (CRUD, вкл/выкл, ручной запуск).
- **Plugs**: автодействия после публикации (например, авто-лайк/авто-репост/авто-комментарий), настраиваемые на канал.
- **Webhooks**: исходящие вебхуки на события, привязка к каналам, тестовая отправка.
- **Third-party**: подключение внешних сервисов (HeyGen, ReelFarm) — импорт контента, вызов функций, submit.

### 8. Аналитика
- Аналитика по каналу (подписчики, охваты, вовлечённость — зависит от провайдера).
- Аналитика по конкретному посту.
- Статистика поста (клики по коротким ссылкам).
- Дашборд платформенной аналитики, звёзды/тренды GitHub-репозитория (маркетинговая фича).

### 9. Биллинг (SaaS)
- Тарифы (tiers), подписка помесячно/годично, пробный период.
- Stripe: checkout, embedded checkout, портал клиента, вебхуки Stripe.
- Промокоды/скидки, купоны (применить/отменить), проверка скидки.
- Пропорциональный пересчёт (prorate), отмена подписки, возвраты (refund charges), список платежей.
- Лимиты по тарифу: число каналов, число постов, AI-кредиты, видео-генерации.
- Партнёрская/агентская часть: маркетплейс, заказы, выплаты, проблемы с выплатами.

### 10. Уведомления
- Внутренние уведомления в интерфейсе + счётчик непрочитанных.
- Email-уведомления (транзакционные + дайджест).
- Объявления (announcements) для всех пользователей, с цветовыми типами.
- Streak / вовлечённость пользователя.

### 11. Публичный API и интеграции
- Public API v1 с ключом и rate-limit: посты (CRUD), список каналов, аплоад, слоты, аналитика, уведомления, генерация видео, триггеры интеграций.
- OAuth-сервер: свои OAuth-приложения (создание, ротация секрета, authorize/token), список одобренных приложений пользователя.
- Node SDK, N8N-нода, Make.com интеграция, Chrome-расширение.

### 12. Админка (суперадмин)
- Список ошибок по платформам, статистика системы.
- Управление объявлениями.
- Мониторинг очередей.

### 13. Фоновые задачи (Temporal workflows)
- Публикация поста в назначенное время + ретраи при ошибке.
- Обновление/refresh OAuth-токенов.
- AutoPost по расписанию.
- Отправка писем, email-дайджест.
- Проверка «пропущенных» постов, streak-воркфлоу.

# ЧАСТЬ B. План создания на Laravel + Vue.js + PostgreSQL + Docker

## B1. Целевой стек

| Слой | Выбор |
|---|---|
| Backend | Laravel 11 (PHP 8.3), Sanctum (SPA-auth) + Passport (OAuth-сервер и публичный API) |
| Frontend | Vue 3 + Vite + Pinia + Vue Router + Tailwind |
| БД | PostgreSQL 16/17 |
| Очереди / расписание | Laravel Queue (Redis) + Horizon + Scheduler (вместо Temporal) |
| Кэш / rate-limit | Redis |
| Хранилище файлов | Laravel Filesystem: local + S3-совместимое (R2/MinIO) |
| Реалтайм | Laravel Reverb / broadcasting (уведомления, прогресс генерации) |
| Платежи | Laravel Cashier (Stripe) |
| Docker | php-fpm, nginx, node (vite), postgres, redis, horizon-worker, scheduler, minio, mailpit |

**Архитектурное упрощение:** Temporal заменяется на Laravel Queue + Horizon + Scheduler
(отложенные джобы с `delay`, ретраи, backoff). Это ключевое отличие от оригинала.

**Слои backend:** FormRequest (DTO) → Controller → Service → Repository/Model. Провайдеры соцсетей —
единый интерфейс `SocialProviderInterface` + реестр провайдеров, никакой платформо-специфичной логики
вне классов провайдеров.

## B3. Рекомендуемый MVP (этапы 0–5 + 10)

Минимально жизнеспособный продукт: аккаунты + организации → подключение 5 каналов →
календарь и редактор постов → медиа → фоновая публикация → биллинг.
Всё остальное (AI, аналитика, автоматизации, публичный API, админка) — после MVP.

## B4. Основные риски

- **Провайдеры соцсетей** — самая трудоёмкая часть: у каждого свой OAuth, лимиты, формат медиа, rate-limit и требования к аппам (review у Meta/TikTok/X).
- **Замена Temporal на Laravel Queue** — нужна аккуратная идемпотентность джоб и защита от двойной публикации.
- **Хранение токенов** — шифрование и безопасная ротация.
- **Лимиты тарифов** — должны проверяться централизованно, а не в каждом контроллере.
- **Генерика провайдеров** — никакой `if ($provider === 'facebook')` вне классов провайдеров.
